# 📝 WORKLOG PROTOCOL — Правила журнала работ

> **Версия:** 1.0 · **Дата:** 2026-07-28

---

## 🎯 Зачем

Две Наи (opus + 5.1) работают над одним проектом. Чтобы не наступать друг другу на ноги и знать что делает другая — **КАЖДАЯ запись в worklog обязательна**.

---

## 📂 Где worklog

**GitHub:** `WORKLOG.md` в корне репо `naytea-source`.

**Альтернатива (если нет git):** `/var/www/shared/worklog-naytea.md` на VPS.

---

## 📋 Формат записи

Каждая запись — секция, начинающаяся с `---`:

```markdown
---

## [2026-07-28 14:30] Ная — START: Переключатель баз данных

**Задача:** Добавить переключатель источников (D1/linkmark/brandsearch/wipo) над вкладками поиска.

**Файлы (планирую):**
- src/app/page.tsx
- src/lib/i18n/translations.ts (новые ключи db.*)
- src/lib/rospatent-d1.ts (обновить search)

**Статус:** В работе
```

После завершения:

```markdown
---

## [2026-07-28 16:45] Ная — DONE: Переключатель баз данных

**Что сделано:**
- Добавлен state dbSource в page.tsx
- UI: 5 кнопок над вкладками поиска
- D1 API обновлён: поиск по text + right_holder + registration_number
- Логика: при выборе D1 → /api/rospatent/search
- 3 языка (RU/EN/ZH)

**Коммит:** abc1234
**Деплой:** https://naytea.ru/ (проверено, работает)

**Статус:** ✅ Завершено
```

## 🚦 Жизненный цикл задачи

```
START → в работе → [проблема?] → DONE
                    ↓
              BLOCKED (нужна помощь)
```

### Статусы
- **START** — начала задачу
- **IN PROGRESS** — работаю (обновляй каждые 30 мин если задача долгая)
- **BLOCKED** — нужна помощь Бро или другой Наи
- **DONE** — завершено, закоммичено, задеплоено
- **CANCELLED** — отменили

---

## 🤝 Передача задачи другой Нае

Если задача нужна другой Нае:

1. Записать в worklog: `## [дата] Ная — HANDOFF: [задача] → Ная2`
2. Положить файл с описанием в `/var/www/shared/inbox/naya2/` (или `naya/`)
3. Написать Бро: «Передала задачу X Ная2, файл в inbox»

**Файл в inbox:**
```
/var/www/shared/inbox/naya2/2026-07-28_NAYA-TO-NAYA2_fix-translations.md
```

## 🔒 Правила

### ✅ Обязательно:
1. **Перед началом работы** — `git pull origin main` + прочитать worklog
2. **Старт задачи** — записать START в worklog
3. **Завершение** — записать DONE + commit + push
4. **Передача** — HANDOFF запись + файл в inbox

### 🚫 Запрещено:
1. Править файлы на VPS напрямую (только через git → deploy)
2. Две Наи одновременно правят один файл (конфликт)
3. Деплоить без commit
4. Начинать задачу без проверки worklog (может другая Ная уже делает)

## 📊 Шаблон для быстрого старта

Перед началом работы, Ная/Ная2 выполняет:

```bash
# 1. Получить последнюю версию
cd /home/z/my-project
git pull origin main

# 2. Прочитать worklog (последние 10 записей)
head -100 WORKLOG.md

# 3. Проверить inbox
ls /var/www/shared/inbox/naya/ 2>/dev/null
ls /var/www/shared/inbox/naya2/ 2>/dev/null

# 4. Начать работу
# ... делать задачу ...

# 5. Завершить
git add -A
git commit -m "[Ная] описание задачи"
git push origin main

# 6. Деплой (если нужно)
/home/z/.venv/bin/python3 /home/z/my-project/scripts/deploy-vps.py
```

## 💡 Советы

1. **Работай атомарно** — одна задача = один коммит. Не делай 5 правок в одном коммите.
2. **Описывай коммиты понятно** — `[Ная] fix: переключатель баз на mobile` лучше чем `update`.
3. **Если сомневаешься** — спроси Бро или напиши в worklog `QUESTION: ...`.
4. **Регулярно пушь** — не копи изменения локально, иначе другая Ная не увидит.

---

*Соблюдать неукоснительно. Нарушение = риск потерять работу другой Наи.*
